# 既知の問題と今後の改善候補

日本語化・軽量化・最適化・ロード時間の改善・スマホ操作対応（Phase 0〜6、[マスタープロンプト](MASTER_PROMPT.md)）が終わった時点のまとめです。計測値は [PERF_BASELINE.md](PERF_BASELINE.md) にあります。

## 既知の問題

### 確認できていないこと
- **実機では確認していません**。計測はすべて GPU のない環境（Chrome の SwiftShader、ソフトウェア描画）と、Chrome のスマホ模擬（CPU 4 倍遅延・Fast 4G）で行いました。次の目標は、実機で確認するまで達成したかどうか分かりません。
  - スマホの起動 8 秒以内
  - 試合中 30fps 以上
- **iPhone / iPad（Safari）は未確認です**。
  - iPhone の Safari は Fullscreen API に対応していません。全画面で遊ぶには「ホーム画面に追加」から起動します（[DEPLOY.md](DEPLOY.md)）。横向きの固定はどちらの場合もできません（縦向きのときは「端末を横向きにして遊んでね」と表示します）。
  - 日本語の改行位置の調整（`word-break: auto-phrase`）は Chrome 119 以降だけで効きます。ほかのブラウザでは、長いカタカナ語が途中で折り返されることがあります。

### 目標に届かなかったもの
- **転送量 −50%**：ベースライン比で −24% です（1,189 KB → 900 KB、brotli 後、初回訪問）。
  - 日本語フォントのサブセット 2 本（計 165 KB）を追加したことが、主な理由です。
  - フォントを除くと −38% です。
- **デスクトップの起動 −40%**：この計測環境では −25% 前後です。
  - 起動時間の大半は、ソフトウェア描画でのシェーダーコンパイルと GPU 処理です。
  - Phase 5 で起動時のシェーダーを 121 → 63 に減らしました。この効果は、先にすべてコンパイルする実機（`KHR_parallel_shader_compile` あり）でしか現れず、この環境の数値には出ません。

### スマホの発熱と画質（iPhone 17 での報告を受けて対応）
- 対応したこと：
  - スマホとタブレットは、フレームレート上限 30fps で始まります（「設定 → 画質 → フレームレート上限」）。GPU と CPU の仕事がほぼ半分になります。
  - 画質「低」の解像度を、スマホでは画面の 0.75 倍から 1.0 倍に上げました（「中」は 1.3 倍）。
  - 画質「低」では、インクの波紋と泳いだ跡の計算を省きます。どちらも、インクが塗られたすべての画素で実行されるループです。
  - 熱で重くなったとき、解像度を 0.5 倍まで下げていたのをやめ、0.75 倍で止めるようにしました。
- 画質「省電力」（`saver`）を追加し、スマホの初期値にしました。以前の初期値「低」のまま使っていたスマホは、1 回だけ「省電力」に移します（`q2` に記録。その後の選択は変えません）。解像度は「低」と同じです。
  - 画面効果（グレード、ブルーム、AO、MSAA）を使わず、画面に直接描きます。HalfFloat の描画先と全画面パスがなくなります。色のグレードとビネットは付きません。
  - MeshPhysicalMaterial の追加効果（クリアコート、シーン、虹色、透過）を切ります（`src/core/saver.js`）。インクの表面（`levelMaterial.js`）だけは、シェーダーがクリアコートを使うため残します。
  - 影は 512px、2 フレームに 1 回、キャラクターの影は 12 m 以内だけです。CSS の繰り返しアニメーションとぼかし（`backdrop-filter`）を止めます（`iw-calm`）。リバーブを止めます。
  - メニューを開いている間は 20fps に下げます。
- 全画質で入れたもの：スマホでは HRTF をやめ（`equalpower`）、同時に鳴る音を 24 にしました。画面外のキャラクターは、ポーズの計算を 3 フレームに 1 回にします。30 m 以上先は、髪・ジグル・指も省きます。ミニマップは、スマホでは 0.45 秒ごとに描き直します。HUD の `_restart` の強制レイアウトもやめました。
- 実機で効果を確かめていません。熱くなる場合は、「設定 → 画質」の内容と、FPS 表示の値を教えてください。

### 実行時の負荷として残っているもの（スマホ模擬、1 フレームあたり）
- **キャラクターのポーズ計算**：8 体で約 3 ms。画面外の 3 フレームに 1 回の間引きと、遠くの髪・ジグル・指の省略は入れました。画面内のキャラクターは毎フレーム計算します。
- **キャラクターの三角形数**：1 体あたり約 37,000。体のメッシュに LOD がありません（ブキにはあります）。low では、遠くのキャラクターの影だけ省略しています。
- **音楽**：作曲エンジンが音符ごとに Web Audio のノードを作るため、約 1.5 ms かかります。
- **low 画質でも MeshPhysicalMaterial**：クリアコートなどの計算があり、スマホの GPU ではピクセルあたりの負荷が高めです。見た目が変わるため、「低」では置き換えていません（「省電力」では切っています）。

### 細かい点
- **ミニマップの解像度（low）**：ステージを作るときの画面サイズで決まります。その後ウィンドウを大きくしても、次のステージまで少しぼやけたままです。
- **Service Worker の更新**：新しいビルドを公開すると、開いたままの古いタブは、次に再読み込みするまで古いページのままです。
  - 起動時に全モジュールを読み込むので、古いタブが途中で壊れることはありません。
- **Vercel への公開**（`tools/release.sh`）：`_headers` は Cloudflare Pages 用です。Vercel では使われないため、ハッシュ付きファイルの長期キャッシュが効きません（Vercel 用の `vercel.json` は用意していません）。
- **コントローラー**：`http://` の LAN アドレスでは、ブラウザが Gamepad API を使わせません（https なら使えます）。
- **動作が重いときの案内**：画質が「低」以外で、半分の解像度でも 25fps 未満が 12 秒続いたときに、1 回だけ表示します。「低」ですでに重い端末には、これ以上の案内はありません。

## 今後の改善候補

優先度が高い順です。

1. **実機での計測**：ミドルレンジの Android と iPhone で、次を計測する。結果を見て、動的解像度のしきい値と low の中身を調整する。
   - 起動時間：`npm run measure` の URL を実機のリモートデバッグ先に向ける。
   - 試合中の fps。
   - 発熱による性能低下。
2. **スマホ用のマテリアル**：low では、キャラクターと小物を MeshStandardMaterial（クリアコートなし）にする。見た目の差は、スクリーンショットで比べて判断する。
3. **キャラクターの LOD**：遠くのキャラクター用に、三角形を減らしたメッシュと影用の簡易メッシュを用意する。
4. **起動時の生成物を事前に焼く**：次のものをビルド時に画像にして配信し、スマホでの起動を短くする。
   - 雲のドーム
   - 遠景の反射キューブ
   - テクスチャライブラリ
5. **音楽のノードの再利用**：音色ごとのノードを使い回すか、フレーズを事前にレンダリングする。
6. **転送量**：次のような方法でさらに減らせる。どれも効果は数十 KB 程度です。
   - 試合でしか使わないモジュールを、試合開始時に読み込む。
   - 日本語フォントのサブセットを見直す（使っていない記号を外す）。
   - GLSL の空白・コメントを削る（試算では brotli 後に −15 KB）。
7. **翻訳**：英語と日本語以外の言語。数によって形が変わる語（複数形など）への対応。
